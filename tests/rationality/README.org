This directory holds the benchmark scenarios for verification target T4 of
[[file:../../debate-graph-spec.org]]: machine-checkable instances of the
rationality postulates (closure, direct and indirect consistency,
subargument closure, non-interference/crash-resistance) plus the canonical
loop cases. Each fixture records its *expected labelling* as data; the graph
labeller, once implemented, is diffed against it.

IMPORTANT: the expected labellings below are hand-derived from the theory
and are *pending oracle validation* (milestone M7 of
[[file:../../propositional-fragment-plan.org]]). They are to be regenerated
from the naive ADF oracle and the third-party adf-bdd cross-check, not
from any existing experimental algorithm; until then treat them as
conjectured, not authoritative. Fixtures are not yet in
the default suite (=tests/conftest.py DEFAULT_SCRIPTS=); run one explicitly:

: .venv/bin/python -m pytest tests/script_test.py --script tests/rationality/<name>.fspy

Status legend: [runnable] replays through the prover today (verified);
[spec-only] scenario and expected labelling recorded here, .fspy pending a
design decision noted inline.

* self_attack.fspy [runnable]

Odd loop of length 1: one argument for P resting on the NAF default for P
itself. Postulate exercised: none directly; baseline for loop handling.

Expected labelling, *revised 2026-09-25* (=aida-strict-phase-experimental=):
the ARGUMENTATION FRAMEWORK grounds P UNDEC on both sides, as before, and
that is what the earlier entry recorded. The ISSUE GRAPH is the framework
plus the strict edges read off the unfolded term, and unfolding captures
the default with P's own continuation. A captured presumption is now a
commitment the debate made rather than an assumption, so the remaining
term is the classical proof of P from =(P->false)->P=: it contributes the
strict edge =SelfAttack*= and P[term] is IN. Both modes evaluate to a
value. Before the revision both yielded a suspended focus.

This is the classical reading the author asked for: =~P -> P= is
equivalent to P, so a self-attacking argument derives its conclusion.

* even_loop.fspy [runnable]

Even loop of length 2: P rests on default absence of Q and vice versa.
Expected: grounded P UNDEC, Q UNDEC; preferred labellings {P IN, Q OUT}
and {P OUT, Q IN}; stable the same. Evaluation of issue P: credulous mode
picks the witness labelling with P IN and returns a value; skeptical mode
yields a suspended focus.

The two-labelling expectation only became true of the implementation on
2026-09-25 (=aida-asymmetric-contrariness-guard=). Before then the
document graph had a third stable labelling, "both refutations stand,
neither proof", because the refutations are bare presumptions and the
symmetric guard let them survive against an accepted derivation. This is the key fixture for issue M4 of the
critique: a per-critical-pair strategy can mix the two preferred
labellings and accept both P and Q - the two-stage discipline of
call-by-onus.org Layer 4 must not.

* contested.fspy [runnable]

Contested node without any propositional cycle: pArg argues P from a
*delegated* Q; a counterargument challenges Q resting on its own
delegation. Both sides of Q are presumption-backed, so grounded labels
(Q, term), (Q, context) and (P, term) UNDEC - the V-two correction case.
The CLI evaluation modes diverge: =evaluate datt skeptical= yields OPEN
(the UNDEC attacked side is dropped), =evaluate datt credulous= yields
VALUE with the presumption standing. The .fspy form of
tests/test_evaluate.py::TestContested, exercised through graph / label /
evaluate.

* modus_tollens.fspy [runnable, exposes a known defect]

Strict rule under a strict refutation: =tp= argues P from a *presumed* Q
via the declared axiom =pRule : Q->P=; =t= is a denied refutation of P.
Contraposition of the rule carries the refutation to the premise, so the
required labelling is Q term OUT, Q context IN, P term OUT, P context IN.

Today the compiler fuses the rule with its defeasible premise into one
defeasible edge and generates no transposal, so Q stays IN - the defect
tracked as =aida-strict-layer=. The fixture is in DEFAULT_SCRIPTS so the
CLI path keeps replaying; its compiled form is pinned as a strict xfail in
=test_postulates.py::TestModusTollensFixture=, which flips when the strict
layer lands. Note the defect is NOT that the fragment lacks strict rules:
the implication is strict, its premise is defeasible, and the edge
conflates them. By design decision every implication in this system
contraposes, delegated ones included, so the same fixture with the
axiom replaced by a `by default` implication must behave the same way
except for decisiveness: a strict transposal sinks Q to OUT, a delegated
one leaves Q contested (UNDEC). Both are in =aida-strict-layer='s VERIFY.

* curried_attack.fspy [not in DEFAULT_SCRIPTS, exposes a known defect]

An attack on the intermediate conclusion of a curried implication:
=cArg= derives C from A and B via =abc : A->(B->C)=, and a challenge to
B->C tries to attack it. The attack fails today, because B->C occurs in
the term only as the type of the elimination stack's tail (a context),
so theta-expansion finds no term-side target. Found by the author while
working lesson 5 of the minicourse; tracked as
=aida-curried-intermediate-conclusions=, whose two halves (name the
partial application; emit one hyperedge per elimination step) are
recorded there. Its compiled form is pinned as a strict xfail in
=test_postulates.py::TestCurriedAttack=, alongside a test pinning the
cause. Kept out of DEFAULT_SCRIPTS since strict replay raises.

* married_bachelor.fspy [spec-only]

Caminada's canonical consistency example. Defeasible: wears-ring => married;
parties => bachelor. Strict: bachelor -> not married (and, by transposition,
married -> not bachelor). Facts: wears-ring, parties.

Expected: direct consistency must hold - no labelling makes both =married=
and =bachelor= IN; grounded labelling: both UNDEC (the two defeasible
arguments rebut each other through the strict layer, symmetrically).
Failure mode being tested: unrestricted rebut with a strict layer that is
not transposition-closed accepts both conclusions and then derives falsum
(closure + consistency violated).

Pending design decision: the encoding of a *defeasible rule* (as opposed to
a defeasible premise). Candidates: (a) rule as axiom, antecedent from a
presumption (premise-defeasibility only); (b) the rule proposition itself
delegated (=by default= on the implication). The choice changes which
attacks exist and belongs to the instantiation mapping of
debate-graph-spec.org section on T4.

* contamination.fspy [spec-only]

Non-interference / crash-resistance (Caminada-Wu). Two disconnected
components: (1) any simple debate, e.g. the even_loop pair; (2) an isolated
strict contradiction: axioms a : A and na : A -> false, giving strict edges
to both sides of A (edges marked CONTR).

Expected: the labels of component (1) are identical with and without
component (2) present. Failure mode being tested: ex falso contaminating
unrelated components - CONTR must propagate only along dependency edges
(debate-graph-spec.org, strict layer).

Pending: needs the CONTR edge-marking pass to exist before an expected
labelling file can be diffed; the scenario itself is expressible today.

* support_cycle.fspy [spec-only]

Two arguments supporting each other's open obligation: argument for P with
obligation Q, argument for Q with obligation P; no presumption anywhere.

Expected labelling, *corrected against the ADF oracle during M0/M7*
(the original conjecture said grounded = both OUT; that is the *stable*
answer, not the grounded one): grounded leaves a mutual-support cycle
UNDEC on both nodes; the two-valued models are {both IN} and {both OUT};
stable semantics selects both OUT. The evidential intuition ("support
transmits acceptance, it does not create it" - no free lunch from support
cycles) is captured by stable, while grounded merely refuses to decide.
See test_support_cycle_grounded_is_undecided in tests/test_oracles.py.
Note the fixture is cyclic, hence outside the acyclic fragment: the graph
compiler refuses it (CyclicDebateNotSupported) and only the oracle labels
it.

* begging_the_question.fspy [spec-only]

Question-begging capture (debate-graph-spec.org section 2.4): an attack on
an argument for A whose counterargument itself presumes the contrary of A,
grafted non-capture-avoidingly so the rootstock captures the assumption.
Expected: the composite labels A IN via the argument from contradiction;
the attack edge is neutralized. Pending: canonical-assumption naming must
be a checked invariant before this can be a stable fixture (same section).

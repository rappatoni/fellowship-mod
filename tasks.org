Discovered 2026-09-15 while tutoring lesson 3. =evaluate_debate=
(core/comp/evaluate.py:177) always takes sigma := =grounded_labels(graph)=;
the mode then only picks the wing at each UNDEC *scaffold*, independently,
via =_wing_choice=. The specification is different:
[[file:propositional-fragment-plan.org]] Layer 4 and the "Step 1: choose a
witness labelling first" section of [[file:call-by-onus.org]] require
credulous mode to choose existentially a labelling in which the issue is
IN, and then to evaluate the whole term against that fixed sigma.

So the implementation is a *local approximation* of the specified
discipline, and issue M4 of the original critique - per-critical-pair
choices are locally greedy and may correspond to no extension - is not in
fact discharged by the code.

On a single contested node the two coincide: the local "discard the UNDEC
attacker" selects exactly the extension in which the proponent wins.
Unverified, and the substance of this task: whether they still coincide
when several contested nodes are linked through edges, so that the local
choices could combine into an assignment no single extension realises.

If the local policy turns out to be sound in this fragment, record the
argument and keep the cheaper implementation; if not, sigma must be chosen
before resolution and the modes reimplemented. Either way the minicourse's
lesson 7 text needs to match the outcome, since it currently describes the
mode table without stating that sigma is always grounded.

*** BACKLOG Name the host hyperedge after its own subargument
:PROPERTIES:
:ID:             aida-host-edge-naming
:AREA:           phd
:PROJECT:        aida
:REPO:           AIDA
:IMPORTANT:      no
:URGENT:         no

:OUTCOME:        A compiled hyperedge is named after the subargument it actually records, so the host edge of the lesson-2 composite reads =cArg= rather than =d2=, and no synthetic theta-expansion name can reach an edge name.
:VERIFY:         Compile a support composite and assert the edge names are the constituent argument names; assert no edge name matches =theta_expand_*=; run the same compilation twice in one process and assert the edge names are identical.
:END:

Found by the author while working lesson 2 of the minicourse, 2026-09-15.
Edge naming is asymmetric: =_Compiler.compile= hands the *debate's* name
straight to =_add_edge_from_body= for the host body, while scions go
through =_scion_name=, which recovers the argument's own name from its
eta-binder. So the host edge of a composite carries the composite's name
even though it records a different subargument's derivation.

Measured on the lesson-2 composite, the eta-binder chain of the body is

: outermost -> innermost: ['d2', 'theta_expand_cArg_4379018016', 'cArg']

and the compiler takes the outermost. The truthful name is the innermost,
=cArg=; the middle entry is a synthetic temporary minted by
=Argument._theta_expand= as =theta_expand_{name}_{id(expanded_body)}=.

Two things to fix, the second more than cosmetic:

- peel the eta-wrapper chain and name the host edge after the innermost
  binder, skipping synthetic =theta_expand_*= names - or keep the debate
  name and record the subargument's name in a separate field, so both are
  available;
- the synthetic name embeds =id(expanded_body)=, a memory address. It is
  nondeterministic across runs and meaningless to a reader. Today it
  cannot reach an edge name, because only scions are named from binders
  and a scion is never a theta-expansion wrapper - but nothing enforces
  that, and if a composite is ever used as a scion the graph would grow
  run-dependent edge names, making printed output unstable and any test
  asserting on them flaky.

Diagnostic only at present: =Edge.name= and =Edge.role= are carried for
printing and never consulted by the labeller or the evaluator, so no
label or normal form depends on this.

*** Issues and suggested fixes

- [ ] /Stepwise protocol despite batching./ Quiet replay still performs one
  send, prompt wait, and response parse for every tactic. Introduce a
  prover-side =check_term= or framed bulk-replay request that returns the
  failing step or one final state without prompt-oriented PTY traffic.
- [ ] /Full proof-state snapshots./ Non-quiet replay repeatedly pretty-prints,
  hashes, and serializes the growing proof term, goals, and declarations. Keep
  quiet intermediate responses and emit at most one full final snapshot.
- [ ] /Proof-term reverse compilation./ Registration parses a proof term,
  translates it into tactics, replays those tactics, and then retains the
  original AST. Add a direct proof-term parser/checker accepting one structured
  certificate; retain tactic replay only for interactive proof construction.
- [ ] /Repeated checking of growing compositions./ Chaining and debate
  construction replay the entire combined term, so repeated composition can
  recheck increasingly large prefixes. Represent compositions as immutable
  DAGs or certificates, cache checks by term and environment hash, and verify
  only the new composition boundary where the calculus permits it.
